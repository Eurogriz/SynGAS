## 5. Наборы реакций

**Gibbs reactor (L0/L1)** — 9 веществ, ограничения по C/H/O/N, графит как отдельная
твёрдая фаза. Альтернатива — Equilibrium Reactor с тремя реакциями:

| ID | Реакция | K(T) |
|---|---|---|
| R1 | CH₄ + H₂O ⇌ CO + 3H₂ | `thermo.equilibrium_constant` (NIST) |
| R2 | CO + H₂O ⇌ CO₂ + H₂ | то же |
| R3 | CH₄ + 2H₂O ⇌ CO₂ + 4H₂ | K₃ = K₁K₂ |
| R4 | C₂H₆ + H₂ ⇌ 2CH₄ | NASA7 GRI30 |
| R5 | 2H₂ + O₂ ⇌ 2H₂O | NIST |

Для L2 — **Heterogeneous Catalytic / LHHW** с базисом скорости на массу катализатора.
Параметры из `model/kinetics.py` — **[НЕ ПОДТВЕРЖДЕНО]**, подключать только после B-01.
Насыпная плотность, порозность и фактор эффективности — [ДОПУЩЕНИЕ].

## 6. Объекты и порядок решения

```
Feed(S-101) → HDS/ZnO (conversion reactor, ТОЛЬКО вспомогательная стадия)
  → Mixer(+S-102,+S-103) → Heater(E-101, +4 695,5 кВт)
  → Gibbs/Equilibrium R-101 (adiabatic, ΔT = −6,1 K)
  → Heater/Cooler R-201 (Q = +88 844,1 кВт, T_out = 1123,2 K, approach 10 K)
  → Cooler E-201 (Q = −34 737,4 кВт, T_out = 623,2 K, NO condensation)
  → Cooler E-202 (Q = −47 850,6 кВт, T_out = 313,2 K, WITH condensation)
  → Separator V-201 → S-108 + S-109
```

Logical operations: `Adjust` для CO₂/C → SN = 2,0; `Set` для p; `Spreadsheet` для
SN = (H₂−CO₂)/(CO+CO₂); `Recycle` — **отсутствует** в базовой схеме (не «закрыт руками»).
`Case Study` для T/p/S/C/CO₂/C/O₂/C; оптимизатор — после валидации кинетики.

## 10. Дополнение V5 (блок аммиачного конвертора)

В HYSYS изотермический `Plug Flow Reactor` для синтеза NH₃ **не подходит**:
промышленный конвертор — это 2–4 адиабатические секции с промежуточным
охлаждением или холодным вбросом. Схема для переноса:

| объект HYSYS | настройка | соответствует |
|---|---|---|
| `Converter` ×3 (adiabatic, ΔP по секции) | P = 200 бар, T_in каждой секции 703,15 K | `model/converter.py: adiabatic_beds` |
| `Heat Exchanger` между секциями | доводка до T_in следующей | 37,2 МВт промежуточного охлаждения |
| кинетика | Temkin–Pyzhev: α = 0,654, k₀ = 6,5·10¹³ кмоль/(м³_кат·ч) × **k_scale = 0,2134**, E_a = 159,4 кДж/моль | `kinetics.ammonia` |
| равновесие | log₁₀K_a = −2,691122·log T − 5,051925e−5·T + 1,848863e−7·T² + 2001,6/T + 2,689 | сверено с NIST Shomate: ≤ 12,6 % |
| термодинамика | Peng–Robinson + идеальные φ (φ = 1 принято явно) | контур 4 |
| компонент NH₃ | энтропийно-энтальпийный набор NIST-JANAF (Shomate) | `data/nist_shomate.json` |

Ожидаемые числа прогона (Россия, 0 °C/101325 Па, GHSV 10 000 ч⁻¹ в
**нормальных** м³): X(N₂) за проход 25,4 % (без калибровки 31,4 %), выход
14,6 мол.% NH₃ (без калибровки 18,6 %), пик постели 845,3 K, подъёмы по
секциям 142/48/28 K, объём катализатора 52,9 м³, ΔH при температуре постели
−53,4 кДж/моль NH₃, увязка с контуром 1,045 по тоннажу NH₃.

Базис GHSV в HYSYS-настройке (`Basis → Standard Volume`) обязан совпасть с

контакта. Если поставщик задаёт GHSV иначе, пересчёт обязателен

### 11.3 Что считать «совпадением» по реформеру

Полоса собственной неопределённости модели по X_CH₄ (`docs/30_v5_uncertainty.md`,
`model/uncertainty.py`): огибающая ±0,008…±0,023 по X_CH₄, в среднем ±0,014,
квадратурно ±0,007 — при T ±2 K, S/C и CO₂/C ±2 %, доле CH₄ −1 %, подходе к
равновесию 10 K, трёх наборах kij и проскоке C2+ через предреформер.
Практический вывод для сверки в HYSYS: **результат, отличающийся от нашего не
более чем на ±0,014 по X_CH₄, неразличим** при тех же неопределённостях входов;
осмысленно сравнивать только отклонения больше полосы. Крупнейший единственный
допуск проектной точки — не состав и не kij, а допущение о подходе к равновесию
(10 K → ±0,023 по X_CH₄): если в HYSYS стоит идеальное равновесие, часть
расхождения объясняется именно этим, и её надо назвать, а не «уточнять EOS».

### 11.4 Коридор активности: что с ним делать при сверке в HYSYS/DWSIM

Аммиачный конвертор в этой модели откалиброван единственным множителем
активности `k_scale`, и два открытых ориентира дают для него несовместимые
значения (0,2134 и 0,5040; отношение ×2,362). Полоса между ними протянута через
конвертор в `model/activity_uncertainty.py` и `docs/32_v5_activity_band.md`;
при сверке в симуляторе вести себя надо так:

1. **Не подгонять точку.** Если HYSYS/DWSIM выдаёт, например, 52,9 м³ катализатора
   при X = 25,35 % — это совпадение с НИЖНИМ краем полосы (нашим проектным
   числом); если 22,4 м³ — с ВЕРХНИМ. Любое значение внутри 22,4…52,9 м³ при
   данной X не опровергает модель и не подтверждает её: оно лежит внутри
   неопределённости активности, а не внутри ошибки расчёта.
2. **Сверять то, что от активности не зависит.** Пик постели при фиксированном
   входе 703,15 K меняется на 0,08 K на всём коридоре (равновесный пинч),
   поэтому T_peak — чистая проверка теплового баланса и схемы охлаждения, но не
   проверка кинетики. Наоборот, выход NH₃ (14,63…17,66 мол.%) и межсекционный
   долг (37,2…42,8 МВт) различают активность и должны сравниваться вместе с
   названным `k_scale`.
3. **Рецикл — отдельная проверка.** Подразумеваемый кинетикой RR падает
   2,944 → 2,332 при настроенном 3,0: если в модели замкнутого контура с
   продувкой и инертами RR устанавливается у верхнего края, это сигнал, что
   стехиометрическое замыкание здесь оптимистично, а не что катализатор «хуже».
4. **Что закрывает полосу.** Только относительная активность из даташита
   производителя на тех же GHSV/T/p (пункты 12–13 `docs/28_v5_vendor_rfi.md`)
   или измеренная на нашей установке (`docs/27_v5_pilot_test_program.md`).
   До этого любые расчёты «оптимизации объёма слоя» обязаны показывать коридор.

### 11.5 Ручной ввод недостающих данных: что это меняет при сверке

С V5.3 все недостающие числа можно внести человеку, не правя `cases/config.json`:
форма — `model/operator_data.py` (61 поле, таблица полей и правила в `docs/33`),
живой ввод — `data/operator_inputs.json` или вкладка «Ручной ввод данных (V5.3)»
панели (`GET`/`POST /api/operator`, действия `validate|save|clear|template|recompute`).

Для сверяющегося с HYSYS/DWSIM это значит три вещи.

1. **Кейс надо собирать из закреплённых чисел, а не из заполнителей модели.** Если
   у вас есть даташит — внесите плотность, ресурс, потолок T, Δp и GHSV с
   провенансом; Python применит их через `load_config()` (`raw["operator_overlay"]`)
   и покажет в `results_v2/operator_data_report.json`. Сравнивать нужно с этим
   состоянием, иначе расхождение припишете модели, а у него просто другой ввод.
2. **Поле с ошибкой не применяется ни наполовины, ни целиком.** Форма с неверной
   единицей или числом вне диапазона отклоняется целиком, и контур 4 падает на
   проверке `operator_overlay`. Если у партнёра модель «сошлась», а у нас нет,
   первым делом смотрите, не отклонена ли форма.
3. **Пока размер не введён — отчёт коридорный.** Точечное совпадение с HYSYS по
   объёму слоя или массе катализатора не является подтверждением модели, если
   соответствующий размер закрыт одним источником: сравнивать надо с полосой
   `results_v2/activity_uncertainty.json`, а фиксацию точки помечать [ЧАСТИЧНО].
   Ввод данных не закрывает контур 5: он закрывает отсутствие данных.
