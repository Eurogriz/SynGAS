# 29. V5 — техзадание (Terms of Reference) на сертифицированную HAZOP

**Статус: ТЗ выпущено. HAZOP не проведена.** Агент не может её провести: по
IEC 61882:2016 исследование выполняется **командой** под руководством
независимого квалифицированного фасилитатора, с зафиксированными P&ID и
подписями. Ни команды, ни замороженных P&ID, ни подписанного ТЗ в проекте нет.

Что уже есть и что это такое: `model/hazop.py` генерирует **лист опроса**
(10 узлов × 11 указателей = 110 строк, 20 из них high-risk по экранной
матрице S×L). Это шаблон-заготовка для будущей команды, а не отчёт:
`certified: false`, каждая строка помечена `[ДОПУЩЕНИЕ] screening entry — not a
team finding`. В V5 в листе исправлен артефакт шаблона (Ni(CO)₄ и «перегрев
трубок» приписывались всем узлам, включая аминную колонну и факел); теперь
**87 из 110 строк остаются GENERIC** — то есть командой должны быть
переписаны или сняты.

## 29.1 Цель и границы

Цель: подтвердить, что проектные решения варианта «Syngas from CH₄,
Ni/MgAl₂O₄, пять целевых продуктов» не создают неприемлемого риска при
эксплуатации, пуске, останове и отказе утилит, и что защитные слои
верифицируемы.

Границы (in scope): подача природного газа → HDS/ZnO → R-100 предриформер →
R-101 пиковый риформер → WHB/E-601 → A-301/A-302 (MDEA + досадка CO₂) →
метанатор → PSA/осушка → контур синтеза (метанол / FT / оксо / H₂ / NH₃) →
компрессор рецикла → сеть PSV/факела → узел остановки и Ni(CO)₄.

Out of scope настоящей фазы: строительство, юрисдкционные нормы,
электроника ESD после SIL-верификации (требуется отдельная IEC 61511
фаза), сейсмика, HAZID предыдущих стадий.

## 29.2 Обязательные участники (роли, а не имена)

| роль | требование | почему без неё не считается |
|---|---|---|
| фасилитатор | независимый от проекта, квалификация по IEC 61882 (сертификат + опыт ≥ 5 исследований аналогичной технологии), ведёт запись | требование стандарта: самостоятельная оценка процесса человеком, который его не проектировал |
| технолог проекта | отвечает на «что будет, если», вправе менять проект | без права менять проект действия не закрываются |
| инженер-механик (статик/режимы) | LMP, ползучесть, цикличность | 20 high-risk строк упираются в перегрев трубок |
| инженер КИП и автоматизации | P&ID, Cause & Effect, SIL | без него «trip» в колонке safeguards — просто слово |
| инженер по безопасности (process safety) | dispersion, fire, explosion, ATEX | модель не считает рассеивание |
| технолог катализатора | Ni(CO)₄, спекание, отравление, смена загрузки | п. 29.4 |
| представитель эксплуатации | пуск/остановка/аварийный режим | 6 из 20 high-risk — STARTUP/SHUTDOWN |
| наблюдатели без права голоса | поставщик катализатора, подрядчик по факелу | — |

## 29.3 Входные документы, без которых сессию начинать нельзя

1. P&ID с ревизией и штампом «frozen for HAZOP» (модель их не имеет);
2. cause & effect матрица + описание ESD;
3. расчёт сети PSV/факела по API 520/521 (в этом проекте — только скрининг по
   критическому истечению, сертификации нет);
4. классификация взрывоопасных зон (ATEX/IECEx) и расстановка датчиков;
5. datasheet катализатора реформинга и потолка температуры
   (`docs/28_v5_vendor_rfi.md`, п. 1–18) — без него строки HIGH T
   не имеют базы сравнения;
6. расчёт LMP труб (материал HP-Nb, 22,4/35,2 МПа при 11 МПа, наклон −0,05;
   100 000 ч) — **не** сертифицированный расчёт по API 530;
7. данные кампании `docs/27` (если уже есть) — см. 29.5;
8. процедура пуска/останова и permit-условия по CO;
9. реестр допущений модели (`data/v2_claims.json`, 59+ записей) — чтобы команда
   видела, что является расчётом, а что — допущением.

## 29.4 Узлы и приоритетная повестка (из чисел этой модели)

Порядок обсуждения = порядок, в котором модель даёт high-risk. Фасилитатор
вправе менять, но не снимать пункт без протокольной причины.

1. **R-101 + R-100, HIGH T**: creep-разрушение трубы по LMP, спекание Ni.
   Модель: T_out 1123,2 K, T_стенки 1271,2 K при потоке тепла 80 кВт/м².
2. **STARTUP/SHUTDOWN по всем никельсодержащим узлам (N01–N03, N07–N09)**:
   окно Ni(CO)₄ при охлаждении в присутствии CO (log₁₀K = 7430/T − 21,90).
   Требование к разрешению: CO < 10 ppm до охлаждения ниже 200 °C; кто меряет,
   где, что блокирует охлаждение.
3. **Δp слоя реформера**: 2,83 бар против предела 3,0 бар, и это **корреляция
   Эргана**, не измерение. Частичная закупорка → перераспределение потока →
   локальные горячие трубы. Требуется: датчик Δp, место отбора, философия трипа
   (см. `docs/27` п. 4).
4. **Конвертор NH₃, пик постели 845,3 K** при предполагаемом потолке
   катализатора 803,15 K (530 °C). Вывод модели зависит **только** от этого
   потолка, а его нет в даташите. Модельная мера: общий вход в секции
   644 K → пик 802,2 K, X за проход 22,5 %, выход NH₃ 12,9 мол.%.
5. **A-301/A-302 (MDEA) + климат middle_east**: нагрев абсорбера, унос воды и
   CO₂ в метанатор, деградация амина выше ~120 °C.
6. **Синтез-контур / компрессор рецикла**: HIGH P + потеря утилит; в модели
   мощность сжатия 5,47 МВт (метанол) / 14,0 МВт (NH₃) — только как ориентир,
   каталожные кривые не открыты.
7. **PSV/факел**: обратное давление, подсос воздуха в холодный коллектор при
   розжиге, радиация по соседнему оборудованию.
8. **Режим Part load / низкий S/C**: равновесная модель завышает конверсию на
   +0,287 X_CH₄ относительно кинетических лабораторных данных — то есть
   реальный аппарат при низкой нагрузке может быть **хуже** по углероду, чем
   показывает проектный расчёт. Проверить случай «потеря 30 % подачи при
   сохранении тепла».

## 29.5 Правила, специфичные для этого проекта

- Ни одно число из `results_v2/` не принимается как доказательство безопасности:
  это расчётный экран. Сертифицируется только **проверка защитного слоя**
  (датчик + логика + элемент + независимость).
- Где модель опирается на допущение, команда обязана либо получить
  первоисточник (даташит, протокол испытаний), либо понизить риск до уровня,
  при котором допущение не важно.
- Запрещено закрывать действие формулировкой «предусмотреть» — только
  «кто / что / чем проверяется / к какой дате».
- Провал контура 5 (валидация) — **вход** в HAZOP, а не её результат: модель
  не валидирована в расчётной точке, поэтому сценарии «хуже, чем расчёт»
  обязаны рассматриваться первыми.

## 29.6 Рисковая матрица и порог действий

Принять матрицу 3×3 листа (S/L → 1…9) как стартовую; high-risk = score ≥ 6.
Для score ≥ 6 обязательна LOPA с независимыми IPL и целевым PFD, заданным
заказчиком (в ТЗ не задаётся: это решение владельца установки). Если IPL
оказывается SIF — дальше IEC 61511, отдельной фазой.

## 29.7 План и объём

| этап | объём | примечание |
|---|---|---|
| подготовительный | 2 дня | freeze P&ID, раздача пакета |
| сессии | 10 узлов × 11 указателей, 4 ч/узел ≈ 40 ч | при 87 generic строках реально — с пересмотром применимости указателей по узлам |
| доработка | 5 дней | действия, LOPA |
| верификация закрытия | 1 день | доказательства, не письма |
| отчёт | 3 дня | worksheet + register + подписи |

## 29.8 Артефакты и критерий «HAZOP считается проведённой»

1. подписанный лист 110+ строк с **командными** (не шаблонными) формулировками
   причин/последствий/защит;
2. реестр действий: владелец, срок, статус, доказательство закрытия;
3. отчёт: узлы, изменения проекта, повторный обезд затронутых узлов;
4. запись в `cases/config.json` и `data/v2_claims.json`: какие допущения сняты;
5. только после этого `results_v2/verification_v2.json → subchecks[HAZOP]`
   становится PASS, и `certified` в `model/hazop.py` переключается на `true`
   **вручную, по приложенному скану подписей** (код не должен сам объявлять
   себя сертифицированным).

## 29.9 Что изменится в модели после HAZOP

- ограничения режима (минимальный S/C, скорость охлаждения, потолок T постели)
  → в `cases/config.json → process` и `kinetics.ammonia.bed_T_max_K`;
- требования к КИП (Δp-датчик, точки отбора, состав аналитики) → в `docs/20`
  (оборудование) и в контракт `data/pilot_schema.json` (измеряемость);
- снятые допущения → метки [ДОПУЩЕНИЕ] → [ПОДТВЕРЖДЕНО] в реестре;
- новый статус подпроверки «certified HAZOP» в контуре 5.

`docs/28` (даташит), `docs/25` (контур 5).
